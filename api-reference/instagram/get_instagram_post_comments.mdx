---
title: "Instagram Post Comments"
openapi: "GET /instagram/post/comments"
---

Pass a canonical public post `url`. `sort=top` (default) returns a small non-paginated popular-comment window. Use `sort=recent` for source pagination.

Each response contains one source page in `items[].comment`, including the comment ID, post ID, author, text, publication time and available like/reply counts. Missing values are null, including reply bodies: a reply count does not mean replies were fetched.

Return `next_cursor` unchanged with the same URL, sort and date filters to continue. Cursors are bound to those inputs and deduplicate earlier pages. The current adapter allows at most three pages or 200 remembered IDs. If more source data remains at that boundary, `truncated` and `source_has_more` are true and `next_cursor` is null. A missing cursor alone does not establish that every historical comment was retrieved.

`since` and `until` accept inclusive YYYY-MM-DD comment-publication dates. They filter the current source page; a filtered empty page can still have a cursor. Enrichments, reply expansion, classification and `scan_pages` are unavailable and return 422. This is a changing public window, not a complete archive.
