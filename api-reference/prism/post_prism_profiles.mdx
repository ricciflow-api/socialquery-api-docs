---
title: "Batch public profiles"
openapi: "POST /prism/profiles"
---

Pass 1–50 objects in `items`, each with `platform`, `handle`, and optional `custom_id`. Results retain input order and caller IDs. Handles may be bare, begin with `@`, or be canonical HTTPS profile URLs. URLs must match the selected platform; redirects, credentials, query strings and fragments are rejected.

**Supported platforms:** Instagram, TikTok, YouTube, Twitter, Threads, Twitch, Snapchat, Truth Social, Bluesky, Kwai, LinkedIn and Facebook. Social profiles use [ScrapeCreators](https://docs.scrapecreators.com/), YouTube uses its [official API](https://developers.google.com/youtube/v3/docs/channels/list), Bluesky uses its [public API](https://docs.bsky.app/docs/api/app-bsky-actor-get-profile), and LinkedIn uses [ScrapeBadger](https://docs.scrapebadger.com/). Other platform values return `unsupported`, with no final charge.

Truth Social is limited to prominent publicly accessible accounts. Facebook gated pages are rejected. LinkedIn's `id` is the returned public profile slug (`ext.id_kind: public_id`), not a numeric member ID. Twitch partnership and Twitter blue-verification flags remain separate from canonical verification. Kwai counts reflect the public source even when surprisingly small; no values are inferred. Truth Social's HTML biography remains in `ext.bio_html`, with canonical `bio` null. Provider access and available allowance determine whether a live lookup succeeds.

Posts, `since`, per-item `stop_at_id`, and SSE are not implemented. Supplied enrichment options or SSE requests return 422 before spending. The JSON-serialized `items` array must fit the 16,000-character parameter limit.

Every `ok` row contains a canonical Author in `data`. The returned identity must match the input. Unknown follower, verification or location fields remain null; hidden YouTube subscriber counts remain null. Provider errors are not treated as nonexistent accounts. A definitive source miss returns `not_found`.

The request holds one credit per input, or five for a LinkedIn input, then refunds every `not_found`, `unsupported`, `error` and `deferred` row. Each successful profile costs one credit, or five for LinkedIn. Repeated input rows are separate lookups. Include the summed hold in `X-Max-Credits`.

At most four source calls run concurrently, each with a twelve-second timeout. No new source work starts after twenty-eight seconds. Rows left unstarted return `deferred` and cost zero. A provider authentication or quota failure stops new calls to that provider while other providers continue. The response is never cached. Replay the same `Idempotency-Key` for zero-cost replay, or retry only failed/deferred rows with a new key.

For MCP use `execute_endpoint`. The Python skill requires `--allow-mutation`, the batch budget and an idempotency key. Both clients calculate the complete hold before sending the batch.
